# Kebijakan Perubahan Database / Database Change Policy

**Project: {project-name}**

## Tujuan / Purpose

Memberikan aturan yang jelas kapan agen/kontributor boleh melakukan perubahan pada struktur/data database saat bekerja di repositori ini.

Provide clear rules for when agents/contributors may make database structure/data changes.

## Ringkasan / Summary

- Perubahan database (CREATE/ALTER/INSERT/UPDATE) hanya boleh dilakukan setelah mendapat **izin eksplisit** dari user.
- Database changes require **explicit user permission** before execution.
- Penghapusan objek database (DROP TABLE, DELETE massal) **dilarang** — agen hanya boleh menyiapkan skrip tetapi TIDAK mengeksekusi tanpa konfirmasi tegas.
- Destructive operations (DROP TABLE, mass DELETE) are **prohibited** — agents may only prepare scripts but NOT execute without firm confirmation.

## Akses Baca / Read Access

- Agen **DIPERBOLEHKAN** membaca database dan artefak terkait tanpa izin eksplisit.
- Agents **MAY** read database and related artifacts without explicit permission.
- Kegiatan baca meliputi: membaca file SQL, menjalankan query SELECT, membaca struktur schema.
- Read activities include: reading SQL files, running SELECT queries, reading schema structure.

## Aturan Detail / Detailed Rules

### 1. Izin Eksplisit / Explicit Permission

- Sebelum membuat atau menerapkan perubahan schema/data, agen harus meminta konfirmasi eksplisit.
- Before making or applying schema/data changes, agents must request explicit confirmation.
- Permintaan harus menyertakan ringkasan perubahan dan potensi dampaknya.
- Requests must include a summary of changes and potential impact.

### 2. Tidak Ada Penghapusan Otomatis / No Automatic Deletion

- Agen boleh menulis skrip CREATE, ALTER, INSERT, atau UPDATE.
- Agents may write CREATE, ALTER, INSERT, or UPDATE scripts.
- Agen TIDAK boleh menjalankan skrip DROP TABLE, DELETE tanpa WHERE yang aman, atau operasi irreversible lainnya tanpa konfirmasi eksplisit.
- Agents MUST NOT execute DROP TABLE, unsafe DELETE, or irreversible operations without explicit confirmation.

### 3. Cadangan & Migrasi / Backup & Migration

- Untuk perubahan schema, sertakan instruksi rollback atau skrip cadangan.
- For schema changes, include rollback instructions or backup scripts.

### 4. Dokumentasi Perubahan / Change Documentation

- Setiap file SQL baru harus disertai komentar yang menjelaskan tujuan, penulis, dan tanggal.
- Each new SQL file must include comments explaining purpose, author, and date.

### 5. Review dan Persetujuan / Review and Approval

- Perubahan database yang signifikan harus disertai PR untuk review.
- Significant database changes must include a PR for review.

## Contoh yang Diperbolehkan / Allowed Examples

- Menambahkan file SQL baru dengan CREATE TABLE dan komentar penjelas
- Adding new SQL files with CREATE TABLE and explanatory comments
- Menambahkan INSERT contoh untuk pengujian dengan label -- FOR DEV ONLY
- Adding sample INSERTs for testing with -- FOR DEV ONLY label

## Contoh yang TIDAK Diperbolehkan / Disallowed Examples

- Menjalankan DROP TABLE dalam skrip migrasi tanpa izin
- Running DROP TABLE in migration scripts without permission
- Menjalankan DELETE massal tanpa backup dan izin
- Running mass DELETE without backup and permission
