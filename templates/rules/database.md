# Database Rules

**Project: {project-name}**

## Purpose

Provide clear policy for database structure and data changes in this repository.

## Access Rules

- Read-only database access is allowed unless the user explicitly restricts it.
- Database writes require explicit user approval before execution.

## Change Approval

- Ask for confirmation before applying schema or data changes.
- Include a short summary of the planned change and its potential impact.
- Highlight rollback or recovery expectations before execution.

## Safe Change Requirements

- Prefer additive migrations over editing previously applied migrations.
- Include rollback guidance or backup instructions for schema changes.
- Document significant database work in the related module change log.

## Restricted Operations

- Do not execute `DROP TABLE`, unsafe `DELETE`, or other irreversible operations without explicit confirmation.
- Do not run bulk data modifications without approval and a recovery plan.

## Review Expectations

- Route significant database changes through pull request review.
- Note operational impact, verification steps, and rollback expectations.
